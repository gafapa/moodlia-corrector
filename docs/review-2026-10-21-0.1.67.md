# MoodlIA Corrector 0.1.67 review

The reported startup error was compatible with an old persisted content-script registration that did not include the localization modules introduced later. The background already updates registrations, but an old registration can execute before synchronization completes. This state was reproduced in isolated Chromium with a deliberately incomplete legacy registration. The public Moodle page was not inspected or changed.

The stable content entry point now contains its own localization and grading dependencies. It ignores overview and unrelated pages before runtime initialization and returns the grader initialization promise so manual activation waits for saved language settings. Authored grader code lives in `src/content/moodleContent.js`; the generated loadable file remains at the original registered path. No additional browser permissions, external resources, network workaround or machine configuration changes were introduced.

Validation passed: 50 unit tests, 64 Chromium checks and 10 locale checks. Tests include an overview and grader under an old registration without localization, remembered-registration migration, repeat activation, a delayed language-storage response and the eight supported interface languages. Packaging rejected an intentionally modified generated bundle; the original bytes were restored before artifact verification.

The extension ZIP contains 238 files byte-matched to current extension source. SHA-256: `1ed1e4c643e20dd33e8859316a1f21f7dfe89abeb424dc235160b14ff916c8d8`. This is a local candidate, not a Chrome Web Store publication. Reload the unpacked extension at `chrome://extensions`, then refresh existing Moodle tabs to replace their old scripts. Saved provider preferences, keys, criteria and site activation settings are preserved.
