# Extension review: 0.2.1

Date: 28 October 2026. An independent review of the 0.2.1 working tree in four
areas, followed by fixes for every confirmed finding:

- document reading (`pageLayout.js`, `odtLayout.js`, `docxLayout.js`, `reader.js`);
- the service worker;
- the Moodle content script;
- permissions, packaging and documentation.

Most findings were reproduced in Chromium with the built extension and
fictional files, then checked again after the fix. No production Moodle page,
student submission, active browser installation or published release was
modified.

The review found no case of one student's grade or feedback reaching another
student, no cross-site scripting in the panel, no remote loading from documents
and no key leak.

## Findings and fixes

### Document reading

| Priority | Finding | Fix |
| --- | --- | --- |
| P1 | An ODT under 1 KB hung the offscreen reader for more than 3 minutes. Repeated cells (up to 256) and rows (up to 100) multiplied through nested tables in a synchronous loop that neither the page limit nor cancellation could stop. | Repeated cells convert their content once and are cloned. Every table element counts against a 200,000-element budget per document; above it the file stops with an explicit error. The reproduction now fails in 0.1 s. |
| P2 | Hidden text (Word `w:vanish`, ODT `text:display="none"`) was not drawn but was sent as text, so a student could hide instructions for the model that the teacher could not see. | Hidden runs, spans and paragraphs are left out of the text (styles included) and counted in the receipt as `hidden-text-excluded`. |
| P2 | Footnote lookup scanned every note for every reference (8,000 notes: 110 s). | Notes are looked up by id. The same file now takes 44 s, spent drawing one very tall page. |
| P2 | With endnotes, the separator piece used the document body as its source, so every footnote was listed again on its page. | The separator has its own empty source. Footnotes are listed once, on the page of the paragraph that first cites them, and references inside `mc:Fallback` copies are ignored. |
| P2 | A table made only of header rows was not drawn (DOCX and ODT; LibreOffice marks the first row as a heading by default). | Such a table is drawn as one block. |
| P3 | Footnotes cited in repeated header rows were lost, and header-row list numbers were taken out of order, because header rows were converted lazily. | Header rows are converted with their table, before its body rows. |
| P3 | One invalid `w:sym` code made the whole DOCX unreadable; a control-character symbol made the page image fail. | Only printable code points become text; characters XML forbids are removed before a page is drawn. |
| P3 | Text after a mid-paragraph page break stayed on the earlier page. | The paragraph is split at the break and the rest starts the next page. |
| P3 | Moved-from tracked text appeared twice in the text. | `w:moveFrom` (and `w:del`) content is excluded. |
| P3 | A default DOCX header after a different first page never reached the text. | Headers and footers are listed on the first page that shows each one. |
| P3 | `rows.indexOf(row)` inside row conversion was quadratic. | Rows are indexed once. |
| P3 | A percentage table width was passed to CSS without the usual check. | It is validated like other lengths. |
| P3 | ODT endnotes were drawn as page-bottom footnotes. | They follow the body after a separator. |
| P3 (suspected) | Stale or partial saved page breaks would turn the rest of a document into one oversized page. | When a saved page holds half a page more than fits, the whole document is measured instead. |
| P3 (privacy) | DOCX `FILENAME` field results were drawn and sent, against "requests omit original filenames". | `FILENAME` results are left out of the page and the text. |

### Correction (service worker)

| Priority | Finding | Fix |
| --- | --- | --- |
| P2 | Decoding a 20 MB attachment took about 700 MB and 4.4 s (`Uint8Array.from(atob(...), mapper)`). | A preallocated array is filled in a loop (or `Uint8Array.fromBase64` where available). |
| P2 | A page's text was split from its image at block boundaries: the image went with the start of the text, the "visual content attached" line with the rest and no image. The second block reported a missing image. | A page that fits in a block starts a new block. A longer page keeps its image with the fragment that ends its text. |
| P2 | DOCX and ODT files now need a vision model: a text-only Ollama model that read DOCX in 0.1.77 refused every DOCX/ODT. | With an Ollama model that reports no image input, DOCX and ODT page images are left out, the text is sent alone, and the receipt reports `page-images-not-sent`. PDF pages and image files still need a vision model. |
| P3 | Two 19.5 MB images in one block made a request of about 53 MB, above the body limit of remote APIs. | Blocks also hold at most 32 MB of image data. |
| P3 | Deadlines were not raised with the limits: 30 s per Moodle download, 60 s per local read, 30 minutes per correction. | Two minutes per download, three minutes per read, 60 minutes per correction. |
| P3 | Extra text files were measured in file bytes; their decoded text could exceed Chrome's 64 MiB message limit. | The panel refuses extra text above 600,000 characters before sending it. |
| P3 | A DOCX or ODT named `.pdf` was reported as a PDF in the receipt. | The read format wins. |
| P3 | Prompts named only PDF pages, and the synthesis asked for a "teacher notes" disclosure with no field (which could reach the student's feedback). | DOCX and ODT pages are named; the synthesis says not to mention block processing in `studentFeedback`. |
| P3 | The Moodle origin for downloads with the teacher's cookies came from the message, not the sender. | A content-script request whose page URL origin differs from the sending page is refused. |
| P3 | "Attachment N" in errors did not match the receipt's attachment numbers. | Errors name the file as the teacher sees it. |

### Moodle panel

| Priority | Finding | Fix |
| --- | --- | --- |
| P2 | "Correction applied" was shown when Moodle showed no grade input (a grade locked or overridden in the gradebook) or no feedback box. | The status says what was applied: feedback but not the grade, the grade but no feedback, or neither. |
| P2 | About fifteen panel strings skipped the translation layer (summary titles, detected data, JSON hint, rubric controls, cost labels, two errors); English showed "Mode: Mode:". | All go through the catalog in eight languages (22 new rows); the summary uses the mode without its prefix. |
| P3 | Feedback in the plain-text Moodle editor (`FORMAT_MOODLE`) was written raw; Moodle cleans that format as HTML when showing it, removing text such as `<stdio.h>`. | Feedback is escaped for `FORMAT_MOODLE`; plain text and Markdown stay raw. |
| P3 | The 20 MB / 40 MB limits were only revealed when correcting. | They are shown next to the picker, and an oversized selection is flagged at once. |
| P3 | Any `pluginfile.php` URL containing `/assignsubmission_file/` anywhere was accepted. | The component must follow the context id (`/pluginfile.php/<context>/assignsubmission_file/...`). |
| P3 | The test hook `mca.requestCorrection` replaced the page's extracted data with the caller's. | Data passed in the message is used for that request only. Only extension pages can send these hooks. |

## Not changed

- **List counters** follow each `w:num`. Whether Word continues numbering across
  different `w:num` entries sharing one definition was not verified against
  Word, so this is documented as a fidelity limit.
- **List and heading numbers** are drawn on the page image but are not part of
  the extracted text.
- **LM Studio `json_object`.** Compatible providers receive
  `response_format: { type: 'json_object' }`. The reviewer recalled older LM
  Studio versions requiring `json_schema`; this was not reproduced, and the
  README already requires JSON-object support.
- **Test hooks** (`mca.extractAssignment`, `mca.applyCorrection`,
  `mca.requestCorrection`) remain: the Chromium checks use them, and only
  extension pages can message a content script.
- **A page with thousands of footnotes** is drawn as one tall page (44 s for
  8,000 notes), within the three-minute reading deadline.

## Follow-up: package size and resource use (7 November 2026)

A second read-only review of the content script, the service worker and the
attachment reader looked for over-engineering and wasted resources. These
findings were fixed in the same 0.2.1 package; the counts and archive checksum
in `review-2026-10-28-0.2.1.json` describe the rebuilt package (102 unit tests,
122 browser checks, 10 locale checks).

| Finding | Fix |
| --- | --- |
| The unminified PDF.js build, the QuickJS scripting engine (never loaded: scripting is off) and the no-WebAssembly decoder fallbacks (unreachable with `wasm-unsafe-eval` and Chrome 116) were bundled. | The minified legacy build and only the JBIG2, OpenJPEG and QCMS decoders are bundled. The unpacked extension drops from 9.06 MB to 5.99 MB. |
| The injected script carried each message's English description in all eight runtime catalogs. | Runtime catalogs hold only the translations: 382 KB to 204 KB; the injected script drops from 580 KB to 403 KB. |
| The offscreen document was never closed, and expired page images stayed until the next read. | Expired entries are dropped on a timer; after two minutes with nothing cached or read, the service worker closes the document. |
| A MutationObserver on the whole page and a one-second timer ran while the panel was closed. | They run only while the panel is open; opening it compares the page identity first. |
| The assignment description page was downloaded and parsed for every student. | It is fetched once per assignment; failed fetches are retried. |
| Teacher criteria were written to storage on every keystroke. | They are saved after a 400 ms pause, and at once on a context change, a read or page exit. |

Not changed in this follow-up: the size of the Office layout engines, the
repeated prompt context per evidence block, and the base64 transfer of
attachments to the reader.
