# Closed-Tab Background Error — 0.1.53

The reported error was `Uncaught (in promise) Error: No tab with id`, with
Chrome attributing the rejection to `src/background.js:0`. The action update
handled rejected `enable`/`disable` calls, but left the promise returned by
`chrome.action.setTitle` unobserved. A tab closing between a tab event/startup
enumeration and this API call could therefore produce an unhandled rejection.

The action update now waits for both API operations with `Promise.allSettled`.
Both asynchronous rejection and synchronous invocation failures are consumed.
Invalid tab IDs are ignored before invoking Chrome. This cosmetic toolbar
update cannot propagate a closed-tab failure into the background runtime.

Validation: `npm run check` passed 24 unit tests, syntax checks, and the reader
build. New unit regressions reject both title and enable/disable operations
with the reported error, and exercise synchronous failures and invalid IDs.
`npm run test:browser` passed 26 checks, including closing a real isolated
Chromium tab and updating both grader/non-grader action states while watching
for unhandled rejections. None were emitted by those action updates.

`npm run package` creates the local 0.1.53 candidate. Its accompanying JSON
records source-content comparison and SHA-256. No live Moodle fields or user
browser settings were changed. The internal Chrome errors tab was visible in
the tab inventory but could not be read through this connection; the exact
message was supplied by the user. Existing Chrome error-log entries are not
automatically removed. Reload the updated extension to activate the fix.
