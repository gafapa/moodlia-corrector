# Unsupported Attachment Omission — 0.1.57

The shared attachment-support policy classifies task references, student
submissions, and manually selected files consistently. Known unsupported
formats are omitted before download or local byte reads. Unknown remote
formats can be classified from response headers before reading the body.
Unsupported embedded image formats in DOCX/ODT produce a structured reader
code that skips the affected document and returns its status to the UI.

The compact panel and popup previews show omitted files in red with the word
`Omitido` and a reason, so color is not the only signal. Included/omitted counts
reflect the selection. Runtime reader omissions are matched by file ID and
role. Correction continues with supported evidence, and omitted content is
not sent to the provider. Provider metadata reports only the omitted roles
and unsupported-format reason; the instruction prohibits inventing their
contents and requires noting relevant evidence limitations.

This change does not suppress corrupt-file, authentication, origin, timeout,
or size-limit errors for supported formats. Existing origin restrictions,
processing limits, cancellation, rubric validation, and stale-context checks
remain active. Known unsupported files do not consume supported-upload limits.

Validation: `npm run check` passed 27 unit tests, syntax checks, and reader build.
`npm run test:browser` passed 38 isolated Chromium checks. Coverage includes
ZIP omission without provider filename exposure, no unsupported-reference
download, a supported ODT reference alongside an omitted ZIP, red statuses in
both views, manual ZIP omission before reading bytes, unsupported ODT embedded
media reported back in red, continued processing of valid text evidence, and
malformed ODT rejection before AI. A 50 MB unsupported-upload unit fixture
verifies that its bytes are not required or counted against supported uploads.

A fictional screenshot confirmed red names and readable omission reasons.
The UI detector returned no findings, which is not a full accessibility audit.
`npm run package` builds the local 0.1.57 candidate. Source-content comparison
and SHA-256 are recorded in the accompanying JSON. No real student work was
sent to AI and the user's installed extension was not reloaded.
