# Extension review: 0.1.77

Date: 27 October 2026. An independent review of the 0.1.76 working tree in four
areas (service worker, content script, attachment reader, permissions/UI/storage),
followed by fixes for every confirmed finding. Moodle behaviour was checked
against `MOODLE_405_STABLE` source. No production Moodle page, student
submission, active browser installation or published release was modified.

## Findings and fixes

| Priority | Finding | Fix in 0.1.77 |
| --- | --- | --- |
| P1 | Case criteria were shared by every student. The grader loads its form through `core_get_fragment`, where `add_grade_form_elements` renders the hidden `userid` as `optional_param('userid', 0)`: it is `"0"` for everyone, and the extension preferred it over the URL. Case notes for one student were shown to and sent with the next. | The user comes from the grade form's `_qf__mod_assign_grade_form_<userid>` marker, then the grader URL; a `0` input is ignored. Attempt `-1` resolves to the latest real attempt from the attempt chooser. Criteria stored under the shared `user:0` key are not migrated, so they are not shown to anyone. |
| P1 | Scanned or photographed PDFs exceeded Chrome's 64 MiB runtime message limit at about 15 pages (reproduced: 20 noisy pages, 337 KB file). Each page was a PNG of up to about 4.5 MB of base64. | A page whose PNG exceeds 1.2 MB of base64 is encoded as JPEG (quality 0.85, then 0.7). Page images above 48 MB per PDF stop with an explicit error. |
| P2 | Plagiarism-report and portfolio links share Moodle's `div.fileuploadsubmission` row (`htmllize_tree`). With portfolios enabled, `portfolio/add.php` was downloaded with the teacher's cookies, treated as `.php` source, returned HTML and stopped the correction. | Only `pluginfile.php` links in the `assignsubmission_file` area (path or `?file=` form) are submission files. |
| P2 | A frozen rubric (grade locked or overridden in the gradebook, `DISPLAY_EVAL_FROZEN`) was reported as applied after rewriting its hidden `levelid`; Moodle does not save it. | `.gradingform_rubric.frozen` (also review/view modes) stops the correction before any field changes. |
| P2 | Feedback was written as plain text into an HTML editor field. Paragraphs were lost, `<tags>` became markup, and the textarea and TinyMCE could differ. | Feedback is escaped and converted to `<p>`/`<br>`, then written identically to the textarea, TinyMCE iframe and Atto editable. Plain-text formats keep plain text. |
| P2 | A returned `maxScore` was replaced by the expected value, so "8 of 100" was filled as 8/10 for providers without native schema enforcement. | A different `maxScore` needs repair; a missing one is accepted. |
| P2 | The score example `7.5` could be copied by weak models. | The template uses `null` as a placeholder and the prompt states the 0..max range. |
| P2 | DOCX text boxes appeared up to four times (nested paragraphs plus the VML `mc:Fallback` copy). ODT frames and notes were duplicated; comments (with author) and tracked deletions were read as student text. | Paragraphs read only their own runs; `mc:Fallback`, `office:annotation`, `text:tracked-changes` and `svg:title/desc` are excluded. Charts, SmartArt and embedded objects are reported. |
| P2 | A renamed legacy `.doc` stopped the whole correction with "invalid zip data". | Formats are identified from their bytes. Legacy OLE files, HEIC, GIF/BMP and other archives are skipped as unsupported; a damaged declared PDF/DOCX/ODT still stops correction. |
| P3 | Grading guides and scale grades were silently not filled. | The panel mode says they are filled manually. Full guide support is not implemented. |
| P3 | Translated "grade out of" labels (French, German, Catalan...) gave no maximum. | A grade label with exactly one number states the maximum. |
| P3 | Typing while saved criteria loaded could overwrite them. | Fields stay disabled until their saved value loads. |
| P3 | `finalComment`/`finalFeedback` overrode `studentFeedback`. | The schema key wins. |
| P3 | Two files with the same name got the same `attachmentNumber`. | Ids are compared when both files have one. |
| P3 | SSE `id:` and `retry:` lines failed the stream. | They are ignored. |
| P3 | Evidence-review requests still said "use in the overall grade / studentFeedback". | Review requests state that those instructions apply to notes. |
| P3 | Online-text images could be any same-origin URL, fetched with cookies. | Only the `assignsubmission_onlinetext` file area, checked in the content script and again in the service worker. |
| P3 | The receipt reported extracted text for scanned PDFs (page labels). | `textCharacters` and `representations` use the PDF's own text layer. |
| P3 | Image type came from the name or MIME type. A teacher file without an extension was counted and then silently skipped. | Image types come from the bytes; extensionless files without NUL bytes are read as text. |
| P3 | UTF-16 without a byte-order mark decoded with NULs; Windows-1252 text was measured re-encoded as UTF-8. | UTF-16 is detected from its NUL pattern; limits use the original byte size. |
| P3 | Ollama versions without `capabilities` were refused as lacking vision. | Only an explicit list without `vision` refuses. |
| P3 | Settings-frame tokens could be reused by any frame of the tab for 5 minutes, and were posted to `'*'`. | A token belongs to the first frame that presents it (kept across that frame's reloads); messages use the exact parent or extension origin. |
| P3 | Content scripts could set any AI endpoint or change remembered sites. | Content scripts can only select saved servers and models; remembered sites change only from extension pages. |
| P3 | Duplicate English catalog rows merged different Spanish forms; about 44 errors, two page titles and two literals were not translated. | Duplicates keep separate keys; the strings are translated in all eight languages. |
| P3 | Results were labelled by position; the AI suggestion field had no accessible name. | Labels match by `criterionId`; the field has an `aria-label`. |
| P3 | The privacy policy named version 0.1.65 and omitted two behaviours. | It now covers 0.1.77, filenames mentioned in teacher criteria, and copied course/assignment defaults (`marketplace/` and the website's `public/privacy/corrector.html`). |
| P3 | Packaging copied everything under `extension/`. | Documentation, source maps and hidden files are excluded; the package has 238 files. |

## Not changed

- **Host permission `https://*/*`.** It is needed for arbitrary Moodle
  installations, selected HTTPS AI providers and signed storage redirects to
  hosts that are only known at download time. Moving it to optional permissions
  would break those redirects unless each host is granted in advance. This is a
  documented design decision (`marketplace/dashboard-fields.md`).
- **`use_dynamic_url` for the options page.** It would hide the extension from
  fingerprinting, but the embedded settings frame is created from the Moodle
  page; this was not changed without a reliable way to verify it.
- **Closed shadow root.** The settings token is protected by frame binding
  instead, so tests and accessibility tooling can still inspect the panel.
- **Grading-guide filling.** The guide has per-criterion scores and remarks
  that would need their own schema; the panel now states that they are manual.
- **Dynamic error messages** (with attachment numbers or token counts) remain
  English; the catalog only translates exact strings.
- **PDF.js source-map references** stay in the bundled files because packaging
  verifies them byte-for-byte against the installed dependency.

## Validation

- `npm run check`: 89 automated tests passed (9 new groups).
- `npm run test:browser`: 81 Chromium checks passed, including DOCX text boxes,
  ODT notes/comments/tracked changes, byte-identified formats, scanned-PDF JPEG
  pages, escaped HTML feedback in TinyMCE, a frozen rubric, plagiarism and
  portfolio links, translated grade labels and the Quickform user marker.
- `npm run test:locales`: 10 checks passed. The screenshots it regenerates were
  restored.
- `node scripts/validate-store-materials.mjs`: passed.
- `npm audit --audit-level=moderate`: zero known vulnerabilities.
- Live inference: `node tests/live-pdf-check.mjs` (`MCA_LIVE_TIMEOUT_MS=900000`)
  passed against local `gemma4:e4b` with the new prompts: the fictional
  nine-page PDF with two rubric criteria completed four requests in 96,292 ms,
  returned the expected 10/10 and both rubric selections, kept its
  student-submission PDF receipt and did not describe the PDF as missing. Final
  usage: 4,306 prompt and 981 generated tokens. The harness sets
  `num_ctx = 131072` only for its own requests.

Package: `release/moodlia-corrector-0.1.77.zip`, 238 files, locally generated,
not installed into the user's browser or published.

## Follow-up in 0.2.1

The 4 MB per-file and 10 MB total attachment limits had no recorded rationale
and were stricter than the transfer path needs. 0.2.1 allows 20 MB per file and
40 MB in total. Each file is sent to the local reader in its own message, but
manually added files travel together from the grading page, so 40 MB (about
53 MB of base64) stays below Chrome's 64 MiB message limit. Higher totals would
need those files sent separately.

A new Chromium check sends two 19.5 MB extra files (39 MB), confirms that a
whole image reaches the provider, and confirms that a 58.5 MB set is refused
with the 40 MB message. With it, `npm run test:browser` passes 82 checks and
`npm run check` passes 89 tests. Package: `release/moodlia-corrector-0.2.1.zip`.

0.2.1 also renders DOCX and ODT files as pages, like PDFs. That change, its
comparison with LibreOffice and its checks are in
[`office-page-rendering.md`](office-page-rendering.md).

These results do not establish arbitrary-document grading accuracy, every
Moodle theme or provider, store approval or production deployment.
