# Assignment Reference Documents — 0.1.51

Documents linked or embedded in the assignment description now enter the
correction request as assignment references. Extracted student files remain
student submissions, and manually uploaded files retain an additional-material
role. The assignment metadata lists references separately from submissions.
Original filenames and Moodle URLs remain excluded from provider prompts.

The extension downloads reference contents only when correction is requested.
It uses authenticated same-origin HTTPS downloads without redirects and the
same local reader as student work. Both groups share the 4 MB per-file,
10 MB aggregate-input, 60,000 attachment-text, and 12-image limits. An
inaccessible, unsupported, unreadable, or oversized reference stops correction
instead of silently omitting task requirements.

Attachment preparation preserves provenance after PDF/DOCX/ODT extraction.
Prompt sections label text and image-only attachments by role and map image
positions to their source attachment. Both initial and repair requests state
that task explanations, templates, and examples are not student work and
must not receive credit as such. This is a provenance contract in the request;
it does not prove an AI model will always assess authorship or quality correctly.

Local ODT parsing now reads `content.xml` paragraph/heading text and supported
PNG/JPEG/WebP images from `Pictures/`. Archive expansion and text/image limits
apply. Other document formats and embedded-image formats are not silently
converted; export unsupported content to PDF when required.

Validation: `npm run check` passed 22 unit tests, syntax checks, and the local
reader build. `npm run test:browser` passed 24 isolated Chromium checks with
fictional evidence and a loopback provider. New cases cover actual local ODT
reference text/image extraction alongside a submitted text file, preserved
roles for image-only evidence and repair requests, missing-reference download
errors, malformed ODT rejection before AI, and omission of identifying
filenames/URLs. Detection still performs zero reference downloads.

`npm run package` prepares the local 0.1.51 candidate. Byte comparison and
SHA-256 are recorded in the accompanying JSON. No real Moodle submissions were
sent to AI or graded; the live user browser was not reloaded. Earlier live
Ollama results were not repeated for this feature. Reload the updated extension
and Moodle page to activate it after saving any pending Moodle edits.
