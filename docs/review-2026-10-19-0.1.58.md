# Corrector 0.1.58 audit follow-up

All listed actionable findings were addressed locally. The previous 0.1.57 unsupported-format behavior remains covered.

## Changes

- B1: replace rendered-text polling with event-driven checks and a scalar fallback; stop grader monitoring when leaving.
- B2/B3: report manual validation failures in the panel; malformed popup JSON cannot become literal student feedback.
- B4/B6: share normalization, preserve repair flags, and require explicit criterion identity. AI output requires exact IDs; manual JSON may explicitly number criteria. Rubric and maximum changes invalidate a captured grading context.
- B5: serialize attachment text inside JSON values with separate outer role/image metadata. Raw role delimiters cannot forge sibling records. Semantic model prompt injection remains a review concern.
- B7: content scripts match assignment-view URL paths, with a strict grader runtime guard. Unrelated HTTPS pages have no injected scripts. Broad HTTPS host access remains necessary for selected providers, arbitrary Moodle installations, and signed storage.
- B8/B15: erase API keys through an explicit settings action; normalize legacy destination URLs before binding a secret.
- B14: follow at most five validated HTTPS redirects, reject loops/downgrades/URL credentials, and omit credentials outside the original Moodle origin. Read-only temporary webRequest listeners resolve opaque redirect headers. AI-provider redirects remain disabled.
- Remove obsolete content transport/prompt/parser code; share file limits, binary encoding, and manual upload readers. Content script shrank from 3662 to 3097 lines compared with the 0.1.57 archive.
- Validate bundled PDF.js/fflate bytes, worker, fonts, CMaps, WASM, licenses, required manifest assets, and UTF-8 before packaging. Add both popup textarea accessible names.
