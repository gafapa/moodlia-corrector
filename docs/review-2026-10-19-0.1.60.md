# Corrector 0.1.60 named local providers and model selection

Named providers now include Ollama, LM Studio, llama.cpp, LocalAI, and vLLM, alongside generic compatible-server options. Protocol, IP/hostname, port, API path, and full URL are editable and synchronized for every provider, including IPv6. Each provider preserves a non-secret address/model profile. Keys remain session-only and are cleared on active destination changes.

HTTP network servers request optional Chrome access to the specific selected hostname. Permission refusal leaves existing settings unchanged; revoked access prevents a network request. An Origin-removal session rule is limited to the configured HTTP origin and requests initiated by this extension, and is removed when changing destinations. Remote API mode still requires HTTPS. No host application, service, firewall, environment, or CORS setting was changed.

The options page has a searchable native model list with readable names, available parameter/quantization/size metadata, alphabetical sorting, duplicate-ID removal, counts, empty/no-match states, keyboard selection, and a manual exact-ID field. The list adjusts its height to visible results. The grading panel has its own model search with richer labels and retains the configured model while filtering.

Validation: npm run check passed 39 tests; isolated Chromium passed 54 checks. Each newly named provider was exercised against a fictional compatible server. Tests cover IP/IPv6/ports, provider persistence, HTTP permission refusal, revoked access, scoped header rules, model filtering, keyboard input, metadata, deduplication, desktop/mobile overflow, and prior grading regressions. Actual llama.cpp, LocalAI, and vLLM instances were not started or qualified.

Desktop and mobile settings and the grading panel were visually reviewed. The Impeccable detector used a degraded regex fallback because parser modules were unavailable; it reported no findings, but did not evaluate computed contrast.
