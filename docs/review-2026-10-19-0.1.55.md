# Scoped Teacher Criteria — 0.1.55

The panel and popup now expose course, assignment, and concrete-case criteria.
Course identity comes from Moodle's body class or matching course navigation.
Assignment identity uses the activity ID. Case identity uses the grader's form
user/attempt when available, otherwise URL parameters. Case storage separates
attempts. Site origin and installation path isolate all keys.

The shared preference controller synchronizes each active key across extension
views. Navigation changes keys, clears fields that no longer match, and loads
the relevant saved text. Pending writes retain their original key; loading
waits for queued writes, and revision checks prevent stale reads overwriting
new typing or a different context. Missing scope identity disables that field
instead of silently creating global criteria. Clearing a field saves an empty
value only for its current scope.

Provider payloads contain `teacherCriteria.course`, `.assignment`, and `.case`,
without local context IDs or storage keys. The system instruction combines
general guidance with more specific task/case refinements while preserving
rubric precedence and evidence requirements. Legacy global instructions remain
intact and require the explicit copy-to-current-task action to be applied.

Validation: `npm run check` passed 25 unit tests, syntax checks, and reader build.
`npm run test:browser` passed 32 isolated Chromium checks. New coverage includes
site/installation/course/task/student/attempt isolation, changing students and
returning to their saved cases, separate attempts, task/course navigation,
hidden form-user changes without URL navigation, structured criteria in the
actual loopback AI request, durable clearing, and legacy recovery without
changing course/case text. Existing navigation, cancellation, file roles,
technical icon views, and closed-tab error regressions continue to pass.

Fictional panel and popup screenshots were inspected; the UI detector used a
reduced regex fallback with no findings, which is not a full accessibility
audit. `npm run package` creates the local 0.1.55 candidate, with content
comparison and SHA-256 recorded in the accompanying JSON. No real student
work was sent to AI and the user's installed extension was not reloaded.
